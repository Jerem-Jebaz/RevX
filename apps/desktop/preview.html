No-USB Delivery

Feasibility is checked before a boot plan is created.

Host-staged RAM boot

The pinned official ISO and non-executable asset bundle now work. Initial signed assets persist on disk; live media moves into RAM only after boot.

UEFI HTTP Boot

Needs firmware and preboot network support. UEFI alone is not enough, and Wi-Fi support varies by model.

Dell BIOSConnect

Useful reference architecture, but vendor firmware cannot be generalized by this app or used for arbitrary OS images.

Recovery rehearsal

Four backend models pass simulated interruptions; real QEMU now proves a pinned full Ubuntu Server ISO continues from RAM after its EFI and HTTP sources are removed.

Current boundary

Secure Boot, guest-side HTTPS, a real current-OS fallback boot, power-loss recovery, and host boot adapters remain unproven.

Disposable VM Evidence

Real QEMU evidence remains separate from host boot execution.

UEFI + official assets: proven

OVMF selected the run-local FAT source; pinned BOOTX64.EFI, GRUB, and MOK manager hashes matched the official Ubuntu 24.04.4 Server ISO.

Full installer RAM: proven

The complete 3,405,469,696-byte ISO was saved in initramfs, Subiquity mounted, and the installer tty appeared after the HTTP source stopped.

Boot-source removal: proven

QMP deleted the boot USB and vvfat node; the final block list contained only immutable OVMF code and a disposable variables copy.

Remaining gates

Secure Boot is off, the guest handoff is isolated HTTP rather than HTTPS, and a real one-shot fallback/current-OS reboot is still unproven.
